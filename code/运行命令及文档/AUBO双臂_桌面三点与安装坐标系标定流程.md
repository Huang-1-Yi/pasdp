## 1. 当前采用的坐标处理

当前继续沿用已有的安装标定和以各臂 BASE 表达的重力方向：

```text
重力 g_BASE → 物理向上 up_BASE = −g_BASE / ||g_BASE||
已有安装前向 + up_BASE → 已保存的 operator_basis_base
遥操作目标 → BASE 下的 TCP 位姿 → IK → servoJoint
```

当前代码中的两处用途有所区别：

- `calibration.py::base_basis()`：由重力和指定前向构造安装/操作者方向；运行映射使用标定文件中保存的 `operator_basis_base`。
- `workspace.py::DualWorkspace`：在 `gravity_base` 模式下，先使用标定文件的重力，主程序启动时再用读取并核对的安装重力初始化高度方向。高度是 TCP 相对该臂 BASE 原点沿物理向上的投影，并不是距桌面的高度。

上述方向在当前控制循环中不逐帧重新标定。本次不更改控制程序、运行配置、左右臂归位位置或已有标定文件。桌面三点标定作为后续独立工作。

## 2. 需要提供什么数据

**每个点提供该机械臂 BASE 坐标系下的实际 TCP `x、y、z`，不需要关节角。**

如果机器人读数包含完整 TCP 位姿，位置三项即可用于本流程；姿态可额外记录以核对测量一致性。不要提供 TOOL/VIEW 坐标读数、相对位移或尚未到达的目标位置。若从示教器读取，先核对其显示的是 BASE 下的实际 TCP。

| 项目 | 约定 |
|---|---|
| 坐标系 | 每臂自己的 BASE，左臂数据与右臂数据分别记录 |
| 单位 | 推荐米；若用毫米，必须明确注明，计算前统一转换 |
| 测量点 | 使用明确的 TCP 或已标定探针尖端实际到达同一物理标记 |
| 工具设置 | 同一臂测量全程使用相同 TCP 偏置；建议保持工具姿态一致 |
| 安装状态 | 基座、桌面及测量标记在采集期间保持固定 |

机器人返回的法兰位置不等于探针尖端位置，除非当前 TCP 定义恰好就是该尖端。三点法不能替代工具 TCP 标定。

## 3. 点位选择与采集

选取桌角及相邻两条桌边上的标记，三点不共线，且处于同一桌面平面。边缘标记应位于桌面上表面，避免混用桌角顶部与桌边侧面上的点。

```text
          PY：约定的 +Y 方向点
          ↑
          │
          O ───────→ PX：约定的 +X 方向点
        桌角原点

          +Z：垂直桌面向上
```

1. 先约定 +X 的物理含义，例如桌面前向，并选定 O、PX、PY 的标签。选择 +Y 时，应使 `X × Y` 指向桌面上方。
2. 在桌面上作出三个可重复定位的物理标记。点间距离尽量大，以降低位置测量误差对方向的影响。
3. 左臂分别到达 O、PX、PY，静止后记录实际 TCP 的 BASE XYZ。
4. 右臂按相同流程记录自己的 BASE XYZ。
5. 条件允许时每点重复采集几次，保留原始读数并检查重复性，再取平均值。

如果目标包括统一双臂坐标系，应让两臂测量**同一组三个物理标记**，并使用相同的 O/PX/PY 标签。若左右臂各测不同桌角，只能得到各自局部坐标系；需要额外测量两个局部坐标系的关系，才能合并为共同桌面坐标系。

### 数据填写模板

```text
+X 的物理含义：
+Y 的物理含义：

```

## 4. 计算桌面到 BASE 的变换

对每臂分别计算，所有点都以该臂 BASE 表达：

```text
a = PX − O
b = PY − O
x_B = normalize(a)
y_B = normalize(b − x_B * dot(x_B, b))
z_B = cross(x_B, y_B)

R_BASE_from_TABLE = [x_B, y_B, z_B]  # 各列为桌面轴在 BASE 中的表示
T_BASE_from_TABLE = [[R_BASE_from_TABLE, O],
                     [0, 0, 0,         1]]

p_BASE = R_BASE_from_TABLE @ p_TABLE + O
p_TABLE = R_BASE_from_TABLE.T @ (p_BASE − O)
```

上述正交化优先保留 O→PX 作为 X；若两条桌边并非严格垂直，Y 为 O→PY 在 X 垂直平面内的投影方向。应记录原始夹角，避免将采点错误隐藏在正交化中。重复点、共线或近似共线点无法可靠确定该矩阵。

如果两臂测量同一组标记，则：

```text
T_LEFT_BASE_from_RIGHT_BASE
    = T_LEFT_BASE_from_TABLE @ inverse(T_RIGHT_BASE_from_TABLE)
```

这能将右臂 BASE 中的位置转换到左臂 BASE。用于共同桌面/世界坐标时，须明确变换的输入输出方向。

## 5. 桌面方向与重力方向的核对

三点得到的是**桌面坐标系**。重力提供的是物理竖直方向，两者只有在桌面水平时才应一致。

```text
up_B = −g_B / ||g_B||
桌面倾角 = acos(clamp(dot(z_B, up_B), −1, 1))
```

- 若 `dot(z_B, up_B) < 0`，先检查 X/Y 点标签和轴向约定。不能只将 Z 取反而保留 X/Y，否则矩阵会变为左手系。
- 若 Z 向上但存在夹角，检查桌面真实倾斜、TCP 偏置、采点误差和安装重力信息。
- 若目标是严格以桌面为准，使用三点生成的 `R_BASE_from_TABLE`。
- 若目标仍是重力对齐安装坐标系，使用 `z_B = up_B`，将 O→PX 投影到重力水平面得到 X，再计算 `Y = Z × X`；PY 用于核对水平方向与手性。这与当前 `base_basis(gravity, forward)` 的构造方式一致。

验证时至少检查：`R.T @ R ≈ I`、`det(R) ≈ +1`、原点 O 的转换结果、PX/PY 转换后的方向，以及同一物理点由左右臂转换到共同坐标后的误差。理想三点可以建立变换；实际数据的可靠性需要重复采样或额外验证点确认。
