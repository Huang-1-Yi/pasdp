# 双臂 AUBO 1013 数据训练

项目根目录：`/media/disk7t/dp_pro6000`。入口为 `train.py`，训练当前 PADP，
不连接机械臂或相机。参考实现来自 `/media/disk7t/task_padp/0518` 的真机
dataset、视频转换函数和空 runner；复用当前仓库的训练核心和公共工具。

## 数据和动作

输入根目录为 `data/1013`，包含 `replay_buffer.zarr` 和 `videos/<episode>/{0,1}.mp4`。
动作按采集记录原样保留 15 列：左位姿 6、左 DO00/DO01 2、右位姿 6、右 DO00 1。
位姿约定为各机器人基座下的 xyz 米和旋转向量弧度。图像为两相机 RGB，
缩放至 240×320；观测还包含左右位姿和 2+1 维 IO 状态。默认不把 stage 输入模型。

dataset 使用普通滑窗 SequenceSampler；不会沿用仿真 RTV8 的固定批次映射，
所以 shuffle=true。当前 PADP loss 只需要 obs/action，window_info 并非必需。
模型保持 horizon=40、n_obs_steps=1、n_action_steps=1，预测 sample。

## 启动

```bash
cd /media/disk7t/dp_pro6000
CUDA_VISIBLE_DEVICES=0 /opt/miniconda3/envs/sim_torch27_v8/bin/python train.py \
  --config-name=train experiment=padp_real_aubo_1013
```

默认 batch_size=16、300 epochs、从头训练；日志离线保存。
数据源和 cache 路径均可在命令行覆盖。不要同时在多张 GPU 上启动同一个输出目录。

## 缓存及 checkpoint

首次读取会将按控制时间网格对齐的视频帧写入 `data/real_cache/1013/`。
后续从磁盘缓存按样本读取，不复制整个图像缓存到 RAM。
缓存键包含数据路径、shape_meta、所选低维数据、时间戳、轨迹结束索引和视频文件信息。
源数据只读；失败的转换不会被当作完成缓存。
视频帧对齐复用现有 read_video（尾部最多重复 10 帧）；超过其能力的短视频会报错。

当前 TrainPADPWorkspace 的 validation/sample 循环在原代码中被整体注释。
本配置不宣称执行验证；val_ratio=0，按 train_loss 每 20 epochs 保存 latest 和 top-5。
此指标不等于真机成功率，闭环测试仍需单独开展。
恢复训练需要指定原输出目录，并覆盖 training.resume=true。
模型输出的 IO 通道是连续预测值，实际部署还需按采集 IO 定义转换成合法 0/1 指令。

## 小规模检查

```bash
python -m unittest discover -s tests -p test_real_image_dataset.py -v
CUDA_VISIBLE_DEVICES=0 /opt/miniconda3/envs/sim_torch27_v8/bin/python train.py \
  --config-name=train experiment=padp_real_aubo_1013 \
  task.dataset.max_episodes=2 dataloader.batch_size=1 dataloader.num_workers=0 \
  dataloader.persistent_workers=false training.num_epochs=1 \
  training.max_train_steps=1 training.use_ema=false logging.mode=disabled \
  hydra.run.dir=data/outputs/padp_real_smoke/1013
```

max_episodes=2 只用于检查前两条轨迹，会使用独立的缓存键。正式训练必须删除此限制。
