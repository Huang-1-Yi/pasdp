## 1. 问题背景与现象分析

### 1.1 现场故障现象
在运行双臂遥操作（`demo_dual_teleop_aubo_v3.py`）时，当操作员控制机械臂（特别是右臂）向下移动触及工作空间下限位（例如右臂 `-535 mm`）时，机械臂末端会产生剧烈的高频上下抽搐与抖动（Jittering / Chattering）。

### 1.2 根本原因定位
经深入分析底层控制链代码，该抖动由以下三项机制缺陷共同诱发：

1. **核心直接原因：零迟滞“打靶 / 乒乓自激振荡（Ping-Pong Chattering）”**
   - **目标截断**：操作员手部下压时，遥控目标通过 `limit_target` 被硬投影截断在下限：`floor = -0.535 m`。
   - **物理超调**：控制器下发 `-0.535 m`，机械臂向下运动。由于物理机械惯性、伺服滞后和传感器微小波动，实际末端读数（`state['eef_pose']`）在到达边界时必然产生微米级的动态超调（例如短暂跌落到 `-535.05 mm`）。
   - **无死区强行抢占**：在原有 `DualWorkspace.recovery_target` 中，触发容差被设为极小的 `1e-12`，且配置强制 `target_margin = 0.0`。一旦实际高度略低于 `-535 mm`，底层 `_height_recovery` 立即强行抢占控制权，中断遥操并向上拉升；机械臂回升到 `-534.99 mm` 后恢复模式立即解除；此时操作员手部仍在下压，遥控目标再次下发 `-535 mm`，再次超调，再次抢占上拉……
   - **结果**：在 50Hz 伺服周期内系统陷入高频自激振荡（终端疯狂交替打印 `TCP below height boundary; lifting to...` 和 `Height recovery complete`）。

2. **速度硬截断与加速度阶跃（Zero-Jerk 缺失）**
   - 接触限位前，机械臂具有向下速度（例如 $0.05 \sim 0.1\ \text{m/s}$）；
   - 在单一控制周期（20 ms）内，目标高度被强行截断为常数，等价于施加了巨大的减速度（Jerk 冲击）；
   - 配合控制器高增益（`gain: 120`，`servo_a: 3.5`），底层 `servoCartesian` 规划器产生抗震冲激并诱发机械结构反弹。

3. **映射器内部积分饱和（Mapper Windup）**
   - 在限位处操作员手部继续下压时，映射器内部滤波状态 `mapper.pose` 持续向更低的负值积分累加（例如累积到 `-580 mm`）；
   - 导致操作员反向抬手时，机械臂无法即时跟随，必须等手部回抽穿过限位才能响应（粘滞延迟感）。

## 2. v4 核心控制优化方案

针对上述三个诱因，在 `v4` 中重构了高度工作空间管理逻辑，形成 **`DualWorkspaceV4`** 模块，并集成入 `demo_dual_teleop_aubo_v4.py`：

```
                      [操作员手部输入 T265]
                               │
                               ▼
                    [QuaternionPoseMapper]
                               │
                ┌──────────────┴──────────────┐
                │                             │
        (优化二: 软阻尼限位)          (优化二补充: Anti-Windup)
       apply_soft_damping           sync_mapper_anti_windup
      [S-curve 渐进平滑降速]         [截断 mapper.pose 饱和]
                │
                ▼
        [安全位姿待发目标]
                │
                ▼
       [DualAuboRealEnvV3 / AuboInterpolationControllerV3]
                │
                ▼
    [Aubo 底层伺服 servoCartesian (50Hz)]
                │
                ▼
        [RTDE 实际位姿反馈]
                │
                ▼
        (优化一: 迟滞死区容差)
          DualWorkspaceV4
         recovery_target
      [recovery_margin 容差放行]
      [Schmitt Trigger 迟滞回线]
```

### 2.1 优化一：回差死区与恢复容差机制（Hysteresis Deadband & Recovery Margin）
- **物理超调容差（Recovery Margin）**：
  - 区分“控制目标可到达的底线”与“底层保护强行介入的硬底线”；
  - 引入 `recovery_margin = 0.003`（默认 3 mm，支持命令行调整）；
  - 正常跟踪下发目标时，实际反馈在 $[H_{\text{floor}} - 3\text{mm}, H_{\text{floor}}]$ 之间的微小动态超调，判定为合法的机械伺服跟随公差，**不触发 `_height_recovery` 强行抢占**，从而彻底切断高频自激闭环；
  - 反馈校验 `validate_feedback` 允许该 3 mm 容差放行，不发生崩溃报警。
- **施密特迟滞回线（Schmitt Trigger Hysteresis）**：
  - 只有当实际反馈**真正深度跌破**底线（$h < H_{\text{floor}} - 3\text{mm}$）时，才触发底层保护接管；
  - 一旦触发抬升恢复，必须抬升回到安全基准（$h \ge H_{\text{floor}} - 0.1\text{mm}$）才释放控制权，彻底消除边界频繁进出抖动。

### 2.2 优化二：软限位平滑阻尼缓冲（Soft Boundary Damping）
- **软阻尼缓冲区（Soft Zone）**：
  - 设限位上方缓冲厚度 `soft_zone = 0.015`（默认 15 mm，支持命令行调整）；
  - 当末端高度处于 $[H_{\text{floor}}, H_{\text{floor}} + 15\text{mm}]$ 缓冲区内时，计算归一化距离：
    $$\rho = \frac{h_{\text{prev}} - H_{\text{floor}}}{\text{soft\_zone}} \in [0, 1]$$
  - 对向下移动分量（$\Delta h < 0$）应用 Smoothstep S-curve 阻尼平滑系数：
    $$\text{damping} = 3\rho^2 - 2\rho^3$$
    $$\Delta h_{\text{damped}} = \Delta h \cdot \text{damping}$$
  - 当接近限位时（$\rho \to 0$），向下增量平缓过渡为 0，使末端在接触限位瞬间**平滑悬停，完全消除速度阶跃与加速度冲击（Zero Jerk）**；
- **向上运动零阻尼**：
  - 当操作员手部向上抬起（$\Delta h > 0$）时，阻尼系数恒为 $1.0$，保持 100% 灵敏的回抽响应。
- **映射器抗积分饱和（Anti-Windup）**：
  - 在每个遥操作周期，将经阻尼或限位截断后的最终目标高度同步更新至 `mapper.pose`；
  - 抑制虚拟位姿在限位处无限制下潜，操作员反向抬手瞬间**零延迟、无粘滞立即响应**。

## 5. P 键双臂自动路径、I/O 与保存（2026-10-12）

完成启动 H 归位并开启遥操后，按 P 让左臂先到
`left_pose_20261012_144317_446652.json`，再到
`left_pose_20261012_144604_163695.json`。两份文件位于
`diffusion_policy/envs/realword/aubo_t265/config/`，顺序固定；也可通过
`--left-pose-files FIRST.json SECOND.json` 指定两份同格式记录。P 需要启用
`--enable-motion --enable-io`。

P 的完整顺序如下，电平按 `[DO00, DO01]` 表示：

| 阶段 | 左臂 I/O | 物理状态 |
| --- | --- | --- |
| 按 P，准备出发；右臂同步缓慢返回 home | 状态三 `11` | 弯折、吸盘打开 |
| 前往第一点、停稳、前往第二点 | 保持状态三 `11` | 弯折、吸盘打开 |
| 第二点停稳后 | 切到状态四 `10` | 弯折、吸盘关闭 |
| 返回左臂 home、停稳 | 保持状态四 `10` | 弯折、吸盘关闭 |
| 左臂在 home 停稳后 | 切回状态一 `00` | 平铺、吸盘关闭 |
| 两臂均到 home、状态一确认并记入数据 | 保持状态一 `00` | 自动执行 S 的保持、保存与暂停流程 |

先确认 DO 输出锁存达到状态三再出发，第二点连续五份新反馈确认停稳后才请求状态四，
确认状态四的锁存后再返回 home；左臂在 home 停稳后切到状态一并确认锁存。
I/O 确认是非阻塞轮询，2 秒未确认则报错停止；
锁存只证明输出电平，不代表吸盘吸取成功或弯折机构物理到位。

左臂两点路径、左臂返回 home 和右臂返回 home 都经过原来的 `env.set_teleop_target`
与动作/观测累计器，连续录入当前 episode。运动期间保持视频录制与 stage，
主循环继续读取观测和响应按键。P 本身不启动录制，需录入时先按 R。

按 P 时右臂从实际 TCP 开始，以五次平滑曲线缓慢返回其记录的 home，采用原始
1 倍规划速度，TCP 速度上限为 `motion.max_speed`（当前 0.1 m/s）。从 P 开始
忽略右手 T265 的位置控制，到 home 后持续提交同一个固定目标，等待左臂完成。
右臂与左臂都使用各自 `home_file` 中的 TCP 位置和归位锁定朝向。

左臂使用五次平滑 XYZ 曲线，速度上限采用配置的 `motion.max_speed` 乘本段倍率，每轮只推进
最多一个遥操周期。第一点实际 TCP 位置误差小于 5 mm、姿态误差小于 1°，且
线速度小于 10 mm/s、角速度小于 0.05 rad/s，连续五份不同时间戳的反馈确认
停稳后才开始第二段；第二点和返回 home 的完成判断采用相同条件。超过等待期限
会报错并停止控制。P 的 home XYZ 使用现有 `home_file` 中左臂的 `tcp_pose_aubo_rpy`
位置，朝向沿用归位锁定设置，不调用 H 的双臂归位与提前结束录制流程。

P 沿用原来的归位朝向锁定和高度边界，不复现记录的六关节构型。两份记录的朝向
与固定朝向分别相差约 0.014°、0.218°。加载时核对左臂 IP/序列号、单位、坐标系、
六维有效值和高度；记录朝向与固定朝向相差达到 1° 时拒绝加载。

先回到 home 的一臂保持目标，直到另一臂也完成并连续五份新反馈确认停稳。左臂
状态一的输出锁存确认后，等待现有观测、动作、stage 累计器共同有效的最后一行
记录到 `00`，再调用与 S 完全相同的 `pause()`：双臂进入保持，保存当前 episode、
停止视频录制，并关闭遥操；左臂保留状态一。不修改原有时间对齐或保存数据流程。

暂停后手柄移动、Z/T 重锚定和 I/O 按钮都不会开启人工位置控制。只有按 E 明确
重新开启遥操，或按 R 开始下一段录制并开启遥操，才从实际 TCP 重新锚定双手并
恢复控制。P 不自动恢复人工控制。P 重复按下会被忽略；执行期间 Z/T/R 暂不
接受，左臂 A/V 被忽略以保持自动 I/O 状态，右臂 C 仍可正常操作。E/S 可以
取消路径并按原规则暂停/保存，H 可以切换到原归位流程，Q/Esc 可以退出；输入
丢失也沿用原来的双臂暂停流程。

## 6. 现场确认的 I/O 对应关系（2026-10-12）

左臂 DO00 控制弯折（0 平铺、1 弯折），DO01 控制吸盘（0 关闭、1 打开）。
之前两路功能备注颠倒，当前 v4 代码、终端提示和本节文档均按现场确认结果更新。

| 左 DO00 | 左 DO01 | 物理状态 |
| --- | --- | --- |
| 0 | 0 | 平铺、吸盘关闭 |
| 0 | 1 | 平铺、吸盘打开 |
| 1 | 1 | 弯折、吸盘打开 |
| 1 | 0 | 弯折、吸盘关闭 |

v4 启动和 H 归位请求左 DO00=LOW、DO01=LOW（平铺、吸盘关闭），右 DO00=LOW。
左臂 A/V 的 `[DO00, DO01]` 循环为 `00 → 01 → 11 → 10 → 00`，依次完成
“打开吸盘 → 弯折 → 关闭吸盘 → 平铺”。右臂夹爪保留接线反转适配，C 从初始 LOW
切换到 HIGH，再切回 LOW。B/D 的忽略规则、P 路径和连续录制接口沿用现有流程。
动作/反馈数据仍保存实际电平 0/1，已有数据文件保持原值。

## 7. v4 自动路径加速（2026-10-12）

P 前往第一点和第一点到第二点的规划速度相对原 P 路径乘 2，P 第二点回 home
乘 4；H 归位在原有 2 倍基础上再乘 2，即采用基础归位的 4 倍。对应常量位于
`demo_dual_teleop_aubo_v4.py` 顶部：`P_POINT_SPEED_SCALE=2`、
`P_RETURN_HOME_SPEED_SCALE=4`、`V4_HOME_SPEED_SCALE=4`。

P 同时缩短关节位移估算的规划时长并按倍率放大本段 TCP 速度上限，避免仅改变
一处时长又被另一处速度上限抵消。H 倍率通过环境参数只赋给 v4 的两个控制器
实例，公共 v3 控制器默认倍率仍为 2。遥操、伺服及采样频率保持原配置。

按两份记录的关节角估算，不包含等待输出锁存或最终停稳的额外时间：

| 路段 | 原规划时长 | 新规划时长 |
| --- | --- | --- |
| P 第一点到第二点 | 11.33 s | 5.66 s |
| P 第二点回 home | 22.50 s | 5.62 s |
| H 从第二点回 home | 11.25 s | 5.62 s |

P 当前点到第一点也乘 2，具体时长取决于按键时实际位置和关节角。所有路段保留
五次曲线、实际停稳判定、I/O 顺序、键盘取消和运动过程连续录制流程；最终保存
与暂停规则见第 5 节。右臂在 P 期间仍用原始 1 倍规划速度缓慢返回 home。
